# PROP-SLEEVES v4 — инструкция

Мульти-рукавный маркет-нейтральный бот для проп-счёта на Bybit (demo-субаккаунт HyroTrader / Mubite).
Один процесс, работает на бесплатном Render (регион **Frankfurt**, не US — Bybit и Binance блокируют US-IP).

## Стратегия (все рукава — одна неттированная книга, ребаланс раз в сутки в 01:10 UTC — последний закрытый бар 00:00–01:00, как в обучении ML)

| Рукав | Что делает | Вселенная |
|---|---|---|
| `listing` | шорт молодых перпов (возраст 7–90 дней по самому раннему листингу Bybit/Binance), исключая имена с ростом >30% за 24ч; хедж — равный лонг BTC/ETH/BNB/SOL/XRP | оборот ≥ $20M/сут, ≤30 имён, ≤5% на имя |
| `core` | качество тренда: средняя часовая доходность / вола за 336ч; лонг топ-20%, шорт низ-20%, равные веса | топ-100 по обороту, ≥$10M/сут, возраст ≥30д |
| `ml3`, `ml7` | LightGBM-ранкер (29 признаков: доходности 1–90д, вола, фандинг, premium index, оборот, диапазоны, возраст, бета), цель — доходность минус фандинг за 3/7 дней; лонг топ-30%, шорт низ-30% | топ-150, ≥$10M/сут, возраст ≥30д |
| `fchg` / `fcarry` | фандинг-рукава (exp24a/e): `fchg` — контрарный к 24-часовому изменению суммарного фандинга (рост фандинга = толпа в лонгах → шорт), квантиль 20%, дневной пересчёт с удержанием; `fcarry` — carry по уровню фандинга за 72ч (шорт высокого положительного, лонг отрицательного), пересчёт каждые 8ч. Сами по себе слабы (Sharpe 0.3–0.6), в книге дают +0.3 Sharpe и режут худший день до −2.6% | топ-150, ≥$10M, возраст ≥30д |
| `ml8` (**рекомендуемая продакшн-книга F2** = listing,core,ml3,ml7,ml8,fchg,fcarry) | внутридневная LightGBM-модель с горизонтом 8ч (пересчёт в 01/09/17 UTC); включение `ml8` в SLEEVES переводит бота на ребаланс каждые 8 часов (дневные рукава пересчитываются в 01:10 и удерживаются). Торгует только имена возрастом ≥ `ML8_MIN_AGE_D` (180) дней, веса внутри стороны обратно пропорциональны воле 168ч (`ML8_INV_VOL=1`), вес рукава 2 (SLEEVE_SCALES ml8:2). Исследование с исправленным VT (REPORT §5c): Sharpe 1.67–1.91 по всей сетке параметров; харнесс бота: 2.24–2.44, CAGR ~30%, MDD −9%, все годы в плюсе. **Цена — оборот ~470×/год: при доле мейкер-филлов < 50% включать только дневную книгу** | топ-150, возраст ≥180д |

Комбинация: равные веса рукавов (ml8 — вес 2) → EMA-сглаживание 0.5 → волтаргет 0.6%/день → множитель риска K → капы (лонг 2%, шорт 1.5%, мажоры 30% equity) → долларовая нейтральность → гросс ≤ 2× equity и ≤ лимитов фирмы → полоса ребаланса 30%.

**Волтаргет (исправлен 2026-09-09):** плечо = 0.6% / реализованная дневная вола *незаплечёванной* книги за `VT_WIN_D` (30) дней; дневные доходности equity делятся на действовавший в этот день множитель экспозиции lev·K (журнал `mult_daily` в памяти бота). Прежняя рекурсивная формула (`lev ← lev·target/realised`) была неустойчива — плечо металось между клипами 0.05 и 3.0 (REPORT §5c). `VT_SMOOTH` — опциональная EMA плеча (по умолчанию 0).

## Риск-движок (правила фирмы = пресет `FIRM`)

* `hyrotrader_2step` — 10%+5%, total DD 10% **trailing** от пика equity, daily 5% trailing от пика дня, consistency 40% (только оценка), 3%/сделку, funded: notional ≤2× / маржа ≤25% начального, low-cap ≤5%.
* `hyrotrader_2step_swing` — то же, но статичные просадки (платный Swing-апгрейд; **подтвердить у поддержки письменно**).
* `hyrotrader_1step` — 10%, 6%/4% trailing.
* `mubite_2step` / `mubite_2step_8` — 10% (8%)+5%, total 8% статичный, daily 5%, 10+3 дня, notional 3×/2× на позицию.

K = `BASE_SCALE` × min(1, буфер до пола / (`CPPI_FRAC` × допуск просадки)) × 0.5 при дневном минусе ≥ `DAILY_THROTTLE_PCT` (1%) × 0.35 после взятия цели до набора мин. дней. Флэт до 00:00 UTC при дневном минусе ≥ `DAILY_HALT_FRAC` (50%) лимита фирмы. Общий стоп-латч, если буфер до пола < 10% допуска. Стоп по шорту при росте цены ≥ 30% от входа (watchdog каждые 60 с) + карантин 48ч. Внутридневное пропорциональное сокращение книги, если K упал более чем на 15% (`scale_pass`).

Режимы по результатам симуляций (см. REPORT.md §5b):
* **Челлендж, «спокойный»** (Mubite 8%+5%, DD 10%): `BASE_SCALE=1.0`, `CPPI_FRAC=0.5` → провал ≈0%, медиана обеих фаз ~230 дней на реальных путях, ~87% успеха.
* **Челлендж, «быстрый» с перезапуском**: `BASE_SCALE=1.5..2.0`, `CPPI_FRAC=0.25..0.5`, `ABANDON_FRAC=0.30` → бот сам сдаёт челлендж при буфере ≤30% допуска (флэт, латч, сообщение) — статистически быстрее купить новый (медиана до funded 52–93 дня, 2–3 попытки, сборы $300–400). Требует запаса на повторные сборы.
* **Funded**: перезапуска нет → `BASE_SCALE=1.0..1.5`, `CPPI_FRAC=0.5`, `ABANDON_FRAC=0` (выживание ≈100%, выплаты 15–22%/год).
* Trailing-пол (HyroTrader Standard): `BASE_SCALE=0.75`; выпуклый режим (`K_MAX` > BASE) по тестам не ускоряет — не рекомендуется.

### Готовые наборы переменных

```
# ФИНАЛЬНАЯ КНИГА F2 (REPORT §5h): listing + core + age-free ML3/ML7 (модели *_noage, вселенная ≥90д) + ML8 (q .20)
#   + фандинг-рукава fchg (контрарный к 24ч изменению фандинга, дневной) и fcarry (carry по 72ч уровню, 8ч), полоса 0.5.
# Общие переменные книги F2 (добавлять к каждому пресету ниже):
#   SLEEVES=listing,core,ml3,ml7,ml8,fchg,fcarry ML_MODEL_SUFFIX=_noage ML_DROP_FEATS=age_d ML_MIN_AGE_D=90 ML8_TOP_FRAC=0.2 REBAL_BAND=0.5
# (веса по умолчанию: ml8 2, остальные 1; FUND_TOP_FRAC=0.2). Книга F (без fchg/fcarry) — первый fallback.
# Fallback K3 (если age-free модели на демо ведут себя иначе): те же переменные без ML_MODEL_SUFFIX/ML_DROP_FEATS/ML_MIN_AGE_D и REBAL_BAND=0.4.
# Челлендж Mubite, умеренный старт (мало кэша на повторные сборы)
FIRM=mubite_8_dd10 MODE=challenge PHASE=1 ACCOUNT_SIZE=10000 BASE_SCALE=1.5 CPPI_FRAC=0.5 ABANDON_FRAC=0.30  (+ переменные книги F)
# Челлендж Mubite, смелый режим (есть запас на 2–3 сбора)
FIRM=mubite_8_dd10 MODE=challenge PHASE=1 ACCOUNT_SIZE=10000 BASE_SCALE=2.0 CPPI_FRAC=0.25 ABANDON_FRAC=0.30  (+ переменные книги F)
# Funded Mubite
FIRM=mubite_8_dd10 MODE=funded ACCOUNT_SIZE=10000 BASE_SCALE=1.25 CPPI_FRAC=0.5 ABANDON_FRAC=0 SET_LEVERAGE=5  (+ переменные книги F)
# Дневная книга (fallback при плохом исполнении): те же переменные без ml8, ребаланс раз в сутки
FIRM=mubite_8_dd10 MODE=challenge PHASE=1 ACCOUNT_SIZE=10000 SLEEVES=listing,core,ml3,ml7 BASE_SCALE=1.5 CPPI_FRAC=0.5 ABANDON_FRAC=0.30
# HyroTrader Swing (второй трек): листинг-рукав отключён из-за правила low-cap
FIRM=hyrotrader_2step_swing MODE=challenge ACCOUNT_SIZE=10000 BASE_SCALE=1.0 CPPI_FRAC=0.5 SLEEVES=core,ml3,ml7,ml8 SET_LEVERAGE=10
```

## Переменные окружения

Обязательные: `BYBIT_API_KEY`, `BYBIT_API_SECRET`, `FIRM`, `MODE` (challenge|funded), `PHASE`, `ACCOUNT_SIZE` (начальный баланс).
Рекомендуемые: `TG_BOT_TOKEN`, `TG_CHAT_ID`, `STATUS_TOKEN`, `BYBIT_BASE_URL` (по умолчанию demo).
Риск: `BASE_SCALE` (1.0 для static, 0.75 для trailing), `CPPI_FRAC` (0.5), `VT_TARGET_DVOL` (0.006), `VT_MAX_LEV` (3), `DAILY_THROTTLE_PCT` (1.0), `DAILY_HALT_FRAC` (0.5), `FLOOR_GUARD_FRAC` (0.05), `POS_CAP_PCT` (2), `SHORT_CAP_PCT` (1.5), `STOP_SHORT_PCT` (60 — страховка), `MAX_GROSS_X_EQ` (2), `SET_LEVERAGE` (5; для funded HyroTrader поставить 10, чтобы гросс 2× вписался в маржу 25%).
Стратегия: `SLEEVES` (listing,core,ml3,ml7[,ml8]), `SLEEVE_SCALES` (ml8 по умолчанию 2), `ML8_MIN_AGE_D` (180), `ML8_INV_VOL` (1), `ML8_VOL_H` (168), `ML8_TOP_FRAC` (0.3; финальная книга — 0.2), `REBAL_EVERY_H` (8 при ml8, иначе 24), `VT_WIN_D` (30), `VT_SMOOTH` (0), `UNI_MIN_TURN` (1e7), `UNI_MIN_AGE_D` (30, core), `ML_MIN_AGE_D` (= UNI_MIN_AGE_D; для age-free моделей — 90), `ML_DROP_FEATS` (пусто; для age-free моделей — `age_d`, должно совпадать со spec моделей), `BETA_CAP` (−1 = выкл; 0 = полная бета-нейтрализация книги к BTC через позицию в BTC; 0.1 = мягкий кап), `BETA_WIN_H` (720), `NOTIONAL_BASE` (initial — правило фирмы; equity — только для сравнений в харнессе), `LIST_MIN_TURN` (2e7), `LIST_AGE_MIN_D`/`MAX_D` (7/90), `REBAL_BAND` (0.3; финальная книга — 0.4–0.5), `SMOOTH` (0.5), `REBAL_HOUR_UTC` (1), `REBAL_MINUTE` (10).
Служебные: `DRY_RUN`, `KILL_SWITCH`, `RESET_TOTAL_STOP`, `EQ_PEAK` (пик equity для trailing после потери памяти), `PHASE_BASE`, `BLACKLIST_SYMBOLS`, `STATE_FILE`.
Переопределение правил фирмы: `TOTAL_DD_PCT`, `DAILY_DD_PCT`, `TOTAL_DD_MODE`, `DAILY_DD_MODE`, `TARGETS`, `MIN_DAYS`, `CONSISTENCY_PCT`, `NOTIONAL_X`, `POSITION_X`, `MARGIN_PCT`, `LOWCAP_TURN`, `LOWCAP_PCT`.

## Соответствие исследованию

`v4/diff_check.py` сверяет веса рукавов и комбинированной книги бота с исследовательским движком (bt.py) по датам: после исправлений расхождение 0.0 на всех датах 2022–2025 (кроме осознанного блэклиста RWA/акций). `v4/tests_v4.py` — 26 юнит-тестов (математика рукавов, вселенная и обратно-волатильные веса ml8, прямой волтаргет, риск-движок, планировщик исполнения). `v4/harness_v4.py --ml-panels` — бэктест самого бота с walk-forward прогнозами ML (честный OOS); `--maker-fill` — вероятность мейкер-филла *за попытку* (3 попытки, затем маркет): 0.7 ≈ 97% мейкер-исполнения (оптимистично), 0.33 ≈ 70% (как в исследовании).

## Деплой

1. Репозиторий с содержимым папки `v4/` (включая `models/`). Render → New → Web Service → Frankfurt → Free.
2. Build `pip install -r requirements.txt`, Start `python main.py`. Переменные из раздела выше.
3. Пингер раз в 10 минут на `/` (бесплатный Render засыпает). Диск эфемерный: память бота в `/tmp` теряется при редеплое — бот восстанавливает якорь дня из журнала транзакций и предупреждает в TG, если пик equity для trailing-просадки пришлось сбросить (задать `EQ_PEAK`).
4. `/status?token=...` — полный JSON: equity, K и причина, lev, полы, число позиций/целей, ошибки.

## Демо-этап (обязательный, ≥3 недели)

Критерии зелёного света: realized dvol 0.4–0.7%/день; ни одного дневного халта; расхождение факт/цель книги < 10% gross; **доля мейкер-филлов ≥ 50% — с оговоркой: Bybit demo наливает лимитки по касанию (очереди нет), поэтому демо ЗАВЫШАЕТ долю филлов и подтверждает только механику; честная оценка исполнения возможна только на малом живом счёте (доля филлов + неблагоприятный отбор: цена филла против цены решения)**; нет позиций вне целей (`n_positions ≈ n_targets`); нет повторяющихся ошибок ордеров; ребаланс укладывается в 30 минут (три ребаланса в сутки при ml8); плечо волтаргета в `/status` плавное (без скачков к 0.05 или 3.0).

## Ежемесячно

Переобучение ML-моделей на свежих данных (скрипты `exp6b_noage_final.py` (age-free дневные модели `models/ml_h{3,7}_noage.txt`, spec_noage.json), `exp6b_final_models.py` (старые модели с возрастом — fallback) и `exp17b_final_8h.py` (8h-модель) в исследовательском репозитории; данные Binance Vision) и замена `models/*.txt`. Бот при старте сверяет число признаков модели с конфигом (`ML_DROP_FEATS`) и отказывается стартовать при расхождении. Проверка списка блэклиста (RWA/акции) и правил фирмы.

## Атрибуция по рукавам и правило отключения ml8 (PREREG.md, правило 1)

`ATTRIB_SLEEVES=1`: на каждом ребалансе бот запоминает знаковую $-экспозицию каждого рукава в позиции каждого символа (маргинальная атрибуция: κ = целевой ноционал / сумма взвешенных весов рукавов, экспозиция рукава = κ × его вес — противоположно направленные рукава получают PnL противоположного знака, сумма вкладов равна PnL позиции) и цену; на следующем ребалансе доходность цены по панели умножается на эти экспозиции; дневные корзины копятся в `sleeve_pnl_hist` (в памяти бота), сводка за 90 дней — в `/status` (`sleeve_attrib`: pnl_pct и Sharpe вклада каждого рукава). `ML8_KILL_RULE=1`: если Sharpe вклада ml8 за `ML8_KILL_WIN_D` (180) дней ≤ 0 — множитель веса ml8 1.0 → 0.5; ≤ `ML8_KILL_HARD` (−1.0) или повторно ≤ 0 — 0.0; возврат на шаг после `ML8_KILL_RESTORE_D` (60) дней вклада > 0.5; не чаще одного изменения в `ML8_KILL_MIN_GAP_D` (30) дней; каждое изменение — в лог и Telegram. Правило записано до демо (PREREG.md) и не подстраивается по ходу; в харнессе оно стоит ~0.2 Sharpe (2.47 → 2.28) — цена страховки от мёртвого рукава.

## Замер исполнения (в `execute`, поля статуса `orders`)

`exec_seconds` / `last_fill_seconds` — время от начала ребаланса до последнего филла; `maker_fill_share` — доля ног, закрытых мейкером до финального маркет-раунда; `market_legs`; `adverse_bps_mean` / `adverse_bps_p90` — цена филла против цены решения (со знаком стороны; положительное = хуже). Демо-этап оценивается по этим трём числам (см. PREREG.md), а не по факту «код не падает».

## Замер исполнения на демо (обязательно для книги с ml8)

8h-рукав теряет ~0.3 Sharpe за каждый час задержки исполнения (REPORT §5e): в журнале ребаланса фиксировать время от закрытия бара до последнего филла; норма — ≤ 10–15 минут на весь ребаланс (3 попытки PostOnly, затем маркет). Если типичное время > 30 минут — уменьшить число попыток мейкера или число имён (ML8_TOP_FRAC), либо работать дневной книгой.

## Изменения раунда 3 (ревью Opus, 2026-09-09)

**Риск и учёт.** Выплаты/депозиты — денежные потоки, не результат: `RiskEngine.note_cash_flow(amount)` сдвигает дневной якорь/пик (и пик equity при статическом поле), а волтаргет считает NAV-доходность `(eq_t − flow_t)/eq_{t−1} − 1` (`flow_daily` в состоянии). Харнесс вызывает это при выплате. Правило low-cap (HyroTrader): совокупный гросс low-cap имён ≤ `lowcap_pct` % базы (не обнуление); low-cap = капитализация < `LOWCAP_MCAP_USD` по CoinGecko (`MarketData.refresh_mcap`, кэш 6 ч, неизвестные имена считаются low-cap), при недоступности — прокси по обороту. Биржевой стоп на каждую позицию (`REQUIRE_SL`, по умолчанию для пресетов hyrotrader*): `/v5/position/trading-stop` на `SL_PCT_LONG` / `SL_PCT_SHORT` от входа.

**Правило отключения ml8.** Атрибуция ведёт «теневой» ряд `ml8_shadow` (рукав на полном весе независимо от множителя) — правило измеряет его и умеет вернуть рукав; правило применяется ДО расчёта сигналов (действует в том же цикле); при множителе 0 каденция ребаланса переключается на 24 ч (`REBAL_EVERY_H`), при возврате — обратно.

**Пред-регистрация.** `config.effective_config()` → хэш всех непаролных параметров (89 ключей); бот пишет его в лог и `/status.config_hash`, а при заданном `EXPECTED_CONFIG_HASH` и несовпадении — не стартует. Модели проверяются по списку признаков из `spec*.json` (порядок и имена, не только число); хэш моделей отдельный (PREREG.md).

**Исполнение.** PostOnly-котировки уходят пакетами по 10 (`/v5/order/create-batch`) с разбором кодов по каждому ордеру; пейсинг запросов (POST ≥ 0.12 с, GET ≥ 0.05 с, backoff на 10006/429); `MAKER_WAIT_S` 90 (3 попытки → ≤ ~5 мин до рыночного остатка). Статистика исполнения — за цикл (`stats`) + накопленная (`stats_total`); доля мейкера по нотионалу (`maker_notional_share`) и по реальным филлам с биржи (`maker_share_real`, `adverse_bps_real` из `/v5/execution/list`).

**Цикл.** Планировщик по «должному слоту» (`due_slot`): пропущенный слот (даунтайм) исполняется при первом пробуждении, слот записывается как должный; старт в hh:05 ждёт hh:10, а не следующий час. Дневные рукава при позднем догоне считаются на баре 00:00 (`panel_daily`), как в исследовании. Маски (карантин после стопа, stale/bad данные) применяются ДО нейтрализации и капов. Пул кандидатов `CAND_POOL` 350. Латчи сбрасываются по отдельности: `RESET_TOTAL_STOP`, `RESET_TARGET_HIT`, `RESET_ABANDONED`.
