## A. Критический дефект: позиции вне текущей вселенной никогда не закрываются

`cycle()` строит цены только по символам текущей панели:
```python
prices = {s: (tk.get(s, {}).get('last') or 0.0) for s in close.columns}   # строка 1687
```
а `execute_orders()` пропускает любой символ без цены:
```python
meta, px = instr.get(sym), prices.get(sym)
if not meta or not px or px <= 0:
    continue                                                              # строка 1216
```
Символ, выпавший из вселенной (ранг по обороту > 120, карантин данных, делистинг), исчезает из `close.columns` → цены нет → его позиция **пропускается навсегда**. Это и есть «хвосты» на демо. Тот же код в main.py (строка 1423) — баг живёт с v3.5.

**Подтверждение в diag прогона:** число позиций на бирже растёт монотонно 81 → 376 при ~70 целях (квартальные медианы):
2022Q3 81 · 2023Q2 110 · 2024Q1 145 · 2024Q4 178 · 2025Q3 282 · 2026Q2 366 · 2026Q3 376.

**Следствия для бэктеста:** результат +16.45% CAGR получен книгой, в которой большую часть времени сотни неуправляемых ног. Они (1) держат ноционал, (2) получают/платят фандинг, (3) двигают net-перекос — NET-GUARD активен 69% времени и режет живые цели тяжёлой стороны. Реальная доходность самой стратегии по этому прогону **неизвестна** — ни в плюс, ни в минус. Атрибуция «фандинг +9.41%/год» также некорректна: значительная часть могла прийти от зомби-ног.

Исправление: цены брать для `set(close.columns) | set(poss.keys())` из `tk` (тикеры есть по всем символам), а символы без цены — закрывать маркетом по mark-price или явно эскалировать в TG, но не молча пропускать.

## B. Оборот 202x/год — структурный, а не «дрожание около полосы»

Распределение оборота по часу суток (из diag): час 0 — 36.6%, час 1 — 14.6%, час 12 — 26.3%, час 13 — 9.6%, остальные 20 часов — по 0.4–0.9%. Итого **87% оборота на границах ребаланса ядра (00/12 UTC) и следующем часе** (мейкер-нефилл → маркет). Гипотеза о часовом шуме вокруг полосы 5% не подтверждается: между границами бот почти не торгует.

Значит источник — сам сигнал: mean/std за 336ч с квантилями 20% на 120 именах даёт большой churn состава корзин каждые 12ч (равные веса → каждая замена имени = 2 сделки по 1/24 стороны). Перевод пересчёта «на 12ч вместо часа» не поможет — фактически он уже такой. Работают: (1) гистерезис членства (вход в топ-20%, выход только при падении ниже топ-35%), (2) ранговые/сглаженные веса вместо ступенчатых корзин, (3) ребаланс 24–48ч, (4) частичное сведение к цели.

## C. Прочие дефекты и риски

1. **Волтаргет недооценивает риск** (2.23% оценка vs 2.9% факт без плеча): оценщик считает волу *целевых* весов, а фактическая книга содержит зомби-ноги (A). После фикса A расхождение должно уйти; проверить.
2. **Вселенная без гистерезиса**: топ-120 по обороту пересчитывается раз в сутки; имена на границе ранга входят/выходят → принудительные закрытия/открытия. Нужен буфер (вход ≤100, выход >150) и минимальный оборот выше $300k (для $10k книги с ногами по $90 это допустимо по размеру, но спред в таких именах 10–30 бп, а не 2).
3. **Модель издержек харнесса**: фикс. 2 бп проскальзывания без зависимости от ликвидности и размера; мейкер-филл 50% задан константой. Для имён из третьего-четвёртого десятка по обороту это оптимизм. Нужна калибровка спреда по ликвидности (оценка по тиковым сделкам Bybit из public.bybit.com).
4. **Тейкер 77% исполнений**: reduceOnly всегда маркетом + переход в маркет после одного нефилла. При 12ч ребалансе можно дать PostOnly больше времени (несколько попыток с шагом 5–10 минут внутри часа) — но это уже работа над исполнением, не над сигналом.
5. **Risk3-guard** триггерится по upnl ≤ −2% equity; при капе позиции 5% equity это движение −40% по монете — правило почти не срабатывает, но и не мешает. Ок.
6. **Якорь дня** восстанавливается из журнала транзакций (реализованное) — расхождение с equity фирмы задокументировано в харнессе [V2-4]. В live риск занижен, если рестарт посреди дня с плавающим минусом; флоат-гард частично закрывает.
7. **Демо-специфика**: hedge-mode ноги (FIX-1..3) — актуально для демо; на реальном UTA one-way это не воспроизводится, но код должен оставаться устойчивым.
8. **Харнесс `--pure`** нормирует лимиты объёма на текущий equity (а не номинал) и отключает дневные тормоза — корректно для вопроса «есть ли альфа», но именно поэтому его CAGR нельзя переносить на счёт фирмы.

## D. Статистический вердикт по прогону

Sharpe 0.90 с 95% ДИ [−0.27; 2.07] за 3.96 года — результат неотличим от нуля; 2023 −14.9%; MDD −26% против лимита фирмы 6–8%. Даже без бага A это не проходит челлендж (Calmar 0.63). Стратегию в текущем виде **нельзя деплоить**; бэктест нужно пересобрать на чистых данных с починенным кодом и честными издержками, после чего решать — чинить сигнал или менять.
