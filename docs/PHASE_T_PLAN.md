# Фаза T — настройка под фирму, лестница роста, личный счёт, одно руководство (Opus, 2026-10-28)

Цель владельца: максимум прибыли и скорости, НО первый челлендж пройти с первого раза и funded-счёт не терять. Дальше — рост
(лестница счетов) и перевод заработка на личный счёт, который со временем заменяет проп.

## Факты (подробно — `docs/FIRMS.md`)
- Из Беларуси подходит только **Mubite** (HyroTrader и почти все остальные запрещают Беларусь; Crypto Fund Trader — запасной, ненадёжный). Идёт второй, расширенный поиск фирм.
- Mubite запрещает «account rolling» (несколько своих счетов с одной стратегией, T&C §13.1.7) и копирование между счетами; правило 120 с — лишь автоматический флаг, проверка — вручную при переходе в funded. **Сдвиг сделок на 120 с правило не обходит** (нарушение — сама общая стратегия), риск — провал всех счетов без выплат. Не делаем.
- Легальные пути роста на Mubite: план масштабирования (+25 % за +10 % прибыли за 90 дней, до 2x); последовательная лестница (закрыть счёт -> купить больший челлендж); взнос Two-Step возвращается с первой выплатой.

## Шаги
1. **Быстрый симулятор** (`research/fastsim.py`) — готов, сверен с харнессом (оптимистичен по провалам ~в 1.5-2 раза -> финалистов перепроверять харнессом).
2. **Перебор всех риск-настроек** (`research/fastsim_grid.py`): челлендж (4 варианта счёта: цель 10/8 %, DD 8/10 %) и funded отдельно; отбор на стартах 2022-24, проверка на 2025-26; устойчивость (соседи тоже хороши). Метрики: челлендж — P(провал) минимум, затем срок; funded — P(смерть за год) ≤ ~2-3 %, затем выплаты/год.
3. **Финалисты -> полный харнесс** (`v4/harness_v4.py`), 123+ старта.
4. **Экономика опций** (цель 8 %, DD 10 %, сплит 90 %): P(пройти с 1-й попытки) × выплаты − цена.
5. **Лестница**: симуляция путей (а) один счёт + масштабирование, (б) последовательная лестница 10k -> 25k -> 50k -> 100k -> 200k (закрытие старого), (в) Mubite + личный счёт (выплаты -> личный счёт, агрессивный VT). Итог: деньги через 1/2/3 года, риск.
6. **Ввод/вывод денег в боте** (сейчас НЕ поддерживается: вывод выглядит как убыток -> дневной стоп): автоопределение пополнений/выводов (журнал транзакций Bybit TRANSFER, а при старте на пустом счёте — разница equity с сохранённой = поток), funded-процедура выплаты Mubite (закрыть позиции -> запрос -> не торговать во время проверки -> возобновить). Правило вывода для личного счёта (рабочий капитал, доля прибыли к выводу) — из симуляции.
7. **Личный счёт**: минимальный капитал для книги (~150 позиций, мин. ордер), агрессивные настройки (VT 1.0-1.5 %/день), правовые вопросы РБ (указ № 367, блокировка Bybit) — отметить, не решать за юриста.
8. **Чистая версия**: пресеты `evns/mubite_phase1.env`, `mubite_phase2.env`, `mubite_funded.env`, `personal.env`; старые — в `archive/`; новые хэши в PREREG; `docs/GUIDE.md` — одно пошаговое руководство (покупка, ключи, запуск, смена фазы, выплата, продление ключей через 93 дня, перезапуск, что делать при стопах).
9. Демо Bybit с утверждённой версией -> покупка.
