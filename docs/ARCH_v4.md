# Архитектура бота v4 (рабочее название PROP-SLEEVES) — черновик для ревью

Цель: торговый бот для проп-счёта на Bybit (demo-субаккаунт HyroTrader / Mubite), который
(1) исполняет портфель из нескольких независимых «рукавов» одной неттированной книгой,
(2) держит риск в жёстких рамках правил фирмы (пресеты), (3) исполняет мейкером где возможно,
(4) переживает рестарты на бесплатном Render (эфемерный диск), (5) не имеет слепых зон,
найденных в v3.x (хвосты позиций, зомби, якорь дня).

## 1. Слои

```
data/      Bybit v5 REST: instruments (launchTime, лоты), tickers (turnover24h, fundingRate,
           markPrice, indexPrice), klines 1h (закрытые бары), funding history, wallet, positions,
           transaction-log. Кэш баров в памяти, инкрементальная догрузка (≤ 200 запросов/цикл).
universe/  point-in-time: возраст листинга (launchTime), 24h оборот ≥ MIN_TURN, гистерезис
           (вход ≤ top_n, выход > exit_n), блэклист (RWA/акции/металлы), исключение имён с
           объявленным делистингом (Bybit announcements API) и low-cap по правилу HyroTrader.
sleeves/   каждый рукав = чистая функция (panel, now) -> целевые веса (доли equity), сумма
           модулей ≈ 1; рукава: listing_drift, ts_trend_majors, xsec_core, (ml_ranker), carry.
           Веса рукавов = риск-бюджеты (равная вола) × общий множитель волтаргета.
book/      неттирование весов рукавов -> целевые ноционалы; капы (лонг/шорт/мажоры), гросс-кап
           (≤ GROSS_X номинала), долларовая нейтральность (опционально beta-hedge BTC),
           полоса ребаланса, EMA-сглаживание целей, min_trade, округление лотов.
risk/      пресеты фирм (hyrotrader_2step / hyrotrader_1step / mubite_2step / custom):
           total DD (static|trailing), daily DD (static|trailing intraday), amount from initial,
           consistency 40% (eval), 3%/trade, max notional, max margin, low-cap exposure;
           CPPI-множитель K по остатку бюджета; дневные тормоза (soft/hard) относительно
           лимита фирмы; стоп на цель фазы; карантины.
exec/      план ордеров: сначала reduceOnly-закрытия (в т.ч. ЛЮБЫХ позиций вне целей — фикс
           бага хвостов: цены берутся из tickers по всем символам), затем открытия;
           PostOnly у лучшей цены с таймаутом T (минуты) и повторной постановкой,
           затем маркет; chunking по maxOrderQty; идемпотентные orderLinkId; верификация
           по positions() после отправки.
watchdog/  каждые 60–120 с: equity, дневной trailing DD (пик дня!), общий пол, per-position
           стоп (|upnl|/notional), gross/notional/margin guards, low-cap exposure guard,
           сироты-ордера (cancel), тихая смерть цикла.
state/     JSON в /tmp + восстановление из журнала транзакций; якорь дня фирмы = equity в
           00:00 UTC (mark-to-market), а не realized; хранение пика дня для trailing DD.
ops/       Telegram-алерты, /status JSON, KILL_SWITCH, DRY_RUN, метрики цикла.
```

## 2. Что принципиально иначе против v3.6
* Позиции вне вселенной закрываются всегда (prices по всем символам из tickers); при отсутствии
  цены — эскалация в TG, а не молчаливый пропуск.
* Ребаланс не «каждый час одни и те же веса», а по расписанию рукавов (listing/xsec — раз в
  сутки в 00:xx UTC, TS — раз в неделю) + внутридневные только стражи риска.
* Trailing daily DD HyroTrader: бот хранит пик equity дня и режет риск при использовании
  50–60% лимита от ПИКА, а не от открытия.
* Стопы на позицию по adverse move (шорты ≤ +25–30%), карантин символа после стопа.
* Исключение имён с 24h ростом > 30% из шортов (сквиз-риск) и имён с объявленным делистингом.
* Волтаргет 0.5–0.6%/день по реализованной воле книги + жёсткий гросс-кап.
* Все параметры фирмы — пресет + переопределение env; отчёт о правилах в стартовом сообщении.

## 3. Тестирование
* bot_harness v2 (fake exchange) адаптируется под v4: те же функции, проверка равенства
  весов с исследовательским движком bt.py (селфтест), прогон 2022→2026 на тех же панелях.
* Unit-тесты: округление лотов, план ордеров, капы/нейтральность, правила фирм (trailing DD),
  восстановление состояния.
* Демо-прогон ≥ 3 недели с контролем: расхождение факт/цель книги, доля мейкер-филлов,
  реализованная вола vs цель, отсутствие хвостов.
