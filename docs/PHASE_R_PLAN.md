# Фаза R — поиск результата (Opus, 2026-10-28)

Цель владельца: заработок на проп-челленджах (Mubite 2-step 10k: цель 8 % / 5 %, общий DD 10 %, дневной 5 %; цена ~150-180 $, выплата 80-90 %). Решение принимаем по деньгам: вероятность пройти и ожидаемый результат в $ на одну покупку, а не по Sharpe.

Итог R1 — `docs/STATUS.md` «Фаза R — шаг R1». Кратко: бот не сломан; провал 2026 даёт волатильная треть монет; 16 простых идей слабее F2.

## R3 (сначала) — экономика челленджа в симуляторе бота
- `v4/harness_v4.py --mode challenge --firm mubite_8_dd10 --phases 2 --pure --maker-fill 0.33 --exec-lag-h 1 --starts <каждые 14 дней 2022-01..2026-09>` (env как в Фазе 4 шаг 1: `evns/base.env` + `evns/challenge.env` без BYBIT_/TG_/STATUS_/STATE_/MODEL_DIR/PORT/DRY_RUN; `MODEL_DIR=$PWD/v4/models`). Модели боевые (обучены до 08.2026) -> старты до 2026-08 in-sample для ML; поэтому отдельно: `--ml-panels` с WF-предсказаниями `_oct` (честно) — если харнесс их поддерживает для h3/h7/8h, иначе пометить.
- Для каждого старта: прошёл фазу 1 / фазу 2 / провал (ABANDON, DD) и за сколько дней. Итог по годам и отдельно для стартов 2026.
- Деньги на одну покупку: EV = P(прошёл обе фазы) × E[выплаты за первые 3 мес. funded × 0.8] − 170 $. Funded-часть: `--mode funded --payout-days 30` с тех же дат прохождения. Таблица: база vs V2.
- Правило (записано до прогона): покупать, если EV > 0 на стартах 2026 года И на всех стартах 2022-2026; если EV > 0 только на всех, но < 0 в 2026 — покупать не больше одного челленджа и только после R2; если EV < 0 на всех — не покупать, F2 для пропа не годится.

## R2 — перебор усилений текущей книги (список закрыт до прогонов, 2026-10-28)
Владелец решил: улучшать F2, а не искать замену (согласовано с Opus). Каждый вариант — один прогон `research/exp_hivol.py`-стиля (движок, lag 1 ч, ×1 + стресс ×1.5 / тейкер), база = F2_noconst.
Слабые места F2 по R1: (а) хвосты шортов в «памповых» монетах, (б) провалы до полугода, (в) риск-настройки под правила фирмы не оптимизировались по деньгам.
1. V2: половинный вес трети самых волатильных монет (готово: DEV 2.23).
2. V3: веса всех рукавов ∝ 1/vol (равный риск на монету).
3. V4: шорт-кап по волатильности — |вес шорта| ≤ cap × (медианная vol / vol монеты); лонги без изменений.
4. V5: запрет шортов в монетах из верхнего дециля max30 (самый большой дневной рост за 30 дн) — только шорт-сторона.
5. V6: + рукав skew30 (шорт «перекошенных вверх» монет, веса 1/vol) с весом 1 из 9 — диверсификатор (корр. с F2 0.10).
Ворота: DEV ΔSharpe ≥ −0.10, стресс ≥ −0.10, худшие 6 мес. на DEV не хуже базы −1 п.п., MDD DEV не хуже базы −1 п.п. HOLD — справочно. Из прошедших — лучший по DEV Sharpe; сочетание двух лучших — ещё одна попытка (итого ≤ 6).
Победитель (или база, если никто) идёт в R3.

## R3-бис — политика просадки и риск под челлендж (по деньгам, не по Sharpe)
Владелец (28.10, принято): остановка с остатком бессмысленна. Взнос за челлендж уже потрачен, остаток вывести нельзя; стоящий счёт ничего не даёт (и фирмы закрывают за бездействие). Пробой пола = тот же итог, что ABANDON, поэтому ABANDON по EV не лучше продолжения. Нужна политика «торговать дальше, но умно»; на funded — тем более (счёт = будущие выплаты).
Политики (список закрыт):
- P0: как сейчас (ABANDON 0.30, CPPI 0.25);
- P1: ABANDON выкл., CPPI 0.25 (риск линейно к 0 у пола; FLOOR_GUARD 5 % остаётся последней чертой);
- P2: ABANDON выкл., CPPI 0.5, но K не ниже 0.3 × base до FLOOR_GUARD (не «замерзать» у пола) — новый параметр `K_MIN_FRAC` в `risk.multiplier`;
- P3: P2 + «режим просадки»: при буфере < 50 % допуска вес волатильной трети монет ×0 (книга сжимается до части, которая работает стабильнее, R1).
× VT 0.4 / 0.6 / 0.8 %/день = 12 вариантов на книге-победителе R2. Дневной стоп фирмы и DAILY_HALT не трогаем (пробой = мгновенный провал).
Метрика: EV $ на покупку (P пройти обе фазы × ожидаемые выплаты funded за 3 мес × 0.8 − 170 $) по ~100 стартам; отдельно старты 2026. Funded — те же политики (ABANDON там и так нет).
Код P2/P3 — в боте (`v4/risk.py`, `v4/signals.py`/`main.py`), харнесс использует тот же код; тесты на новые параметры; по умолчанию поведение прежнее.
Перед решением о покупке — сверить правила Mubite на сайте (бездействие, срок, лимиты), https://mubite.com/en/challengeRules.
