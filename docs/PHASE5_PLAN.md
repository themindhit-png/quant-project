# Фаза 5 — автоматизация (решение Opus, 2026-10-27)

Итог Фазы 4, на котором стоит план: книга F2 (ml8 без констант, `alpha_order`), переобучение **раз в 6 мес. (1 янв / 1 июл), expanding**, гэп h+7 дней (h3 10, h7 14, 8h 8 дней). Подробно — `docs/PHASE4_LOG.md`, «Итог Фазы 4».

Принцип: владелец не программист → каждая операция на VPS = одна команда, любой сбой = старое состояние + сообщение в Telegram. Бот и его хэш конфигурации в этой фазе не меняются (кроме п. 4, если его нет).

## 5.1 Сборщик данных Bybit на VPS (каждый час) — главное в фазе
Зачем: через 6 мес. нужны Bybit-данные для решений, отложенных в Фазе 4 (пороги оборота, premium/оборот, OI). Сейчас их нет.
- `ops/collect_bybit.py`: для символов вселенной бота (+ BTC, ETH) дописывает закрытые часовые свечи (OHLCV, turnover), фандинг, premium-index, open interest (1h) в `/opt/propsleeves/data/bybit/<тип>/<YYYY-MM>.csv.gz` (append, без дублей по времени; докачка пропусков при старте до 7 дней назад). Только публичные эндпоинты, без ключей. Использовать существующий клиент `v4/bybit.py`, если подходит.
- systemd timer `propsleeves-collect.timer` в :05 каждого часа (не пересекается с ребалансом 01:10/09:10/17:10 по CPU — проверить, что сборщик < 1 мин). Ошибки 3 часа подряд → сообщение в Telegram.
- Тест в облаке: на записанных ответах API (фикстуры), проверка append/дедупликации/докачки. В облаке Bybit API недоступен — живой прогон только на VPS.

## 5.2 `ops/retrain.py` — переобучение по расписанию (раз в 6 мес.)
- Запускается **в облачной сессии** (здесь есть `data.binance.vision` и CPU; на VPS не хватит памяти/диска — проверить в 5.5 и записать). Владелец раз в полгода пишет «сделай переобучение», затем на VPS `bash ops/deploy.sh --models`.
- Шаги одной командой `python3 ops/retrain.py --cutoff 2027-01-01`: докачать Vision (`dl_binance.py`) → `build_panels.py` до cutoff → `check_panels.py` → финальные модели h3/h7 (`exp6b_noage_final.py`, END = cutoff − 10 / 14 дней) и 8h (`exp17b_final_8h.py`, END = cutoff − 8 дней, признаки `FEATURES_8H`) в `models_new/` → ворота → копия в `v4/models/` + `docs/MODELS.md` (дата, END, хэши файлов, IC).
- Ворота (только техника, без подбора по бэктесту — модель обучена на всём, честного OOS у неё нет):
  1. список признаков в spec = live `compute_features` (T25 / T25c проходят на новых моделях);
  2. предсказания новой и старой модели на последних 30 днях: средний Spearman по датам ≥ 0.5 (иначе что-то сломано в данных);
  3. предсказания не вырождены (std > 0, нет NaN, ≥ 95 % символов вселенной);
  4. для отчёта (не ворота): IC старой модели за прошедшие 6 мес. — это честный OOS, пишется в `docs/MODELS.md` и в отчёт.
  Провал любого → `v4/models/` не трогается, печать причины.
- Гэпы и END — константы в одном месте `retrain.py` со ссылкой на PHASE4_LOG «4.2 ревью».
- Проверка в облаке: прогон с `--cutoff 2026-07-01` в отдельную папку; предсказания на 15-29.09 сравнить с боевыми моделями (обучены до 31.08 — должны быть близки, Spearman > 0.8).

## 5.3 Ежедневно: бэкап состояния и сводка
- `propsleeves-daily.timer` 00:30 UTC: копия `state.json` (только состояние, без `bot.env` с ключами) в `/opt/propsleeves/backup/state-YYYYMMDD.json`, хранить 30 дней; сводка в Telegram: equity, дневной PnL, до ABANDON / до цели, число позиций vs целей, `clip_share`, `dvol_norm`, последние ABORTED. Если бот уже шлёт такую сводку — только бэкап, сводку не дублировать.

## 5.4 `ops/install.sh` — установка на чистый VPS одной командой
Python, venv, `requirements.txt`, клон репо, `/opt/propsleeves/{src,models,data,backup}`, шаблон `bot.env` (ключи владелец вписывает сам), systemd-сервис бота (`Restart=always`) + таймеры 5.1/5.3, `deploy.sh --check` в конце. Идемпотентно (повторный запуск ничего не ломает). На текущем VPS не запускать (там всё стоит) — только `--timers-only` для установки таймеров 5.1/5.3.

## 5.5 CI и проверка ресурсов

- `ops/deploy.sh --check` печатает RAM/диск VPS; зафиксировать в STATUS, хватит ли VPS для `retrain.py` (ожидание: нет → переобучение в облаке, как в 5.2).
