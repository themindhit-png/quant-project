# Рабочий план к регистрации 5 (записан ДО прогонов, 2026-10-31)

Цель: проверить небольшой список улучшений книги F2 по заранее записанным воротам; принятое — одной регистрацией 5 (черновик в
`docs/PREREG.md`), код за переключателями env, по умолчанию поведение рег. 4. Живые параметры, регистрации 1–4 и бот не меняются.
Каждый прогон — строка в `docs/PHASE4_LOG.md`, раздел «Рег. 5», с колонкой «N накопл.» (старт N = 573: 570 по всем прошлым фазам + 3 быстрые
диагностики). Повтор того же варианта — только при найденной ошибке кода («баг: …»).

## Базы
- **База рег. 4**: движок, конфигурация R2 (сигнал на баре i−1, исполнение на i, BASE8), V2 (`HIVOL_MULT=0.5`), предсказания `_noage_oct_r4` /
  `_oct_noconst_r4`, 2022-01 … 2026-10-26: Sharpe 1.99 / 1.51 (×1.5). Воспроизведена бит в бит (`research/phase4_out/FWDCHK_book.csv` = `R4_E_V2.csv`).
- **База-R** — после шагов реализма (ниже). Если реализм сдвигает цифры, все идеи сравниваются с Базой-R.
- **База ML** — Base-R с усреднёнными предсказаниями (5 зёрен × 2 даты конца обучения) — для идей, где переобучаются модели.

## Шаги реализма (класс R — принимаются как факт)
- **R-1 фандинг биржи исполнения.** История ставок Bybit есть только с 2025-01 (дамп VPS). Варианты: (а) Bybit — только как доход/расход,
  сигналы по старому источнику; (б) Bybit — и доход, и сигнал (как в живом боте). На 2025-01 … 2026-10 для монет с данными Bybit, раньше —
  старый источник. База-R = (б). Полная история — скрипт для VPS (`fetch_bybit_funding.py --since 2020-01-01`), после неё R-1 пересчитать.
- **R-2 выгрузка почасовых целевых весов по монетам** (`WEIGHTS_OUT`) — инструмент, не попытка.
- **R-3 минута ребаланса.** Замер по 5-мин ценам (2022-06 …): цена исполнения ног 8-часового ML-рукава (и всей книги) в hh:00 / hh:05 против
  hh:10, средний выигрыш в б.п. на единицу оборота по годам. Правило: выигрыш ранней минуты > 0 в ≥ 4 из 5 лет → в рег. 5 предлагается
  `REBAL_MINUTE` 10 → 1 (плюс проверка на VPS, что часовая свеча финальна к hh:00:30).

## Идеи (основной вариант → второй; второй — проверка плато: если знак Δ×1 расходится с основным, идея отклоняется)
1. **Убрать рукав «изменение фандинга»** (S, основной). Остальные веса как есть (нормировка по сумме весов). Механизм: оборот книги ↓.
   Второй (A): заменить его сигнал остатком изменения фандинга за 24 ч после доходности 24 ч и изменения премии 24 ч (кросс-секционная
   регрессия на каждом решении); принимается, только если проходит ворота A и лучше основного.
2. **Два дневных ML-рукава → один** (S): сигнал = среднее рангов двух прогнозов, вес 2, остальное как у рукавов. Механизм: оборот ↓.
3. **Мягкая граница квантиля в фандинг-рукавах** (M, один вариант): полный вес в верхних/нижних 15 %, линейный спад до 0 к 25 %; равным
   значениям — равный вес (средний ранг). Механизм: оборот рукава фандинга ↓ ≥ 8 %.
4. **Вес 8-часового ML-рукава 2 → 1** (A, основной). Второй: кластерный паритет риска (кластеры: три ML / тренд / листинги / два фандинга;
   вес кластера ∝ 1/σ его «бумажной» дневной доходности по прошлому, ковариации со сжатием 50 % к диагонали, пересчёт раз в квартал,
   внутри кластера поровну; < 90 дн истории — равные веса). Не оба.
5. **Множитель рукава fcarry по известному заранее спреду фандинга** (M): m = clip(S / медиана прошлых S, 0.5, 2), S = средний 72-ч фандинг
   шорт-ноги минус лонг-ноги на момент решения. Второй: рукав выключен, если ожидаемый carry до следующего ребаланса (S·8/72) меньше
   стоимости его перестройки (4.5 б.п. × оборот рукава). Механизм: доход фандинга на единицу оборота ↑.
6. **Волтаргет по риску текущих весов** (M): σ = std дневной «бумажной» доходности текущих целевых весов за 30 дн (основной) → EWMA с
   полураспадом 10 дн (второй). Механизм: разброс скользящей 90-дн. волы (p10–p90) уже, чем у базы.
7. **Бэггинг моделей** (S): 5 зёрен × 2 даты конца обучения (0 и −14 дн), среднее прогнозов, для всех трёх моделей. Плюс показать
   распределение одиночных зёрен. Становится Базой ML.
8. **8-часовая модель на метке со сдвигом на 1 бар** (A, против Базы ML, 5 зёрен парно): метка log(P[i+9]/P[i+1]) − фандинг.
9. **Веса по рангу в ML-рукавах** (A, против Базы ML): линейно (основной) → квадратично.
10. **Метка «нормальный квантиль ранга»** для дневных моделей (A, против Базы ML, 5 зёрен).
Не делаем: метка «цена + фандинг» — уже так (метка = доходность минус уплаченный фандинг).
Батчи 4–5 (исполнение на минутках, новые рукава) — только если останется время.

## Пакет (один раз)
Все принятые (R, S, M, A) вместе в порядке списка; конфликт 4: либо вес 1, либо паритет риска. Ворота класса A против Базы-R (для ML-частей —
против Базы ML). Не прошёл → принимаются только R и S. В конце DSR пакета при N после плана ≥ DSR Базы-R при N до плана; PBO по матрице
«все варианты × 10 полугодий» < 0.25 — иначе только R и S.
